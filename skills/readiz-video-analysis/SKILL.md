# 영상 분석

요청 범위의 내용을 원본 없이도 이해할 수 있게 설명하고, 어떤 자막과 화면을 확인했는지 남긴다. 단순 요약 요청을 게시 작업으로 확대하지 않는다. 글쓰기와 저장을 요청받았다면 사용 가능한 글쓰기와 사이트 저장 스킬로 연결한다.

## 분석 흐름

1. 영상 URL 또는 파일, 제목, 채널, 게시일, 길이와 요청 구간을 확인한다. URL의 시작 시각을 무조건 제거하지 않는다. 기존 분석과 파일이 같은 원본인지 확인해 재사용한다.
2. [확보와 프레임 추출](references/acquisition.md)을 읽고 기존 도구를 확인한다. 공개 영상은 `yt-dlp`로 메타데이터와 자막을 먼저 확보하고, 필요한 영상 구간을 받아 `ffmpeg`로 장면을 추출한다. 로컬 원본은 다운로드 없이 사용한다. 브라우저 캡처는 다운로드 접근 장애나 플레이어 UI 확인이 필요한 경우에 사용한다.
3. 자막과 챕터로 구간별 내용표를 먼저 만든다. 핵심 주제, 사례, 수치, 절차와 인과관계를 적고 필요한 화면 후보를 연결한다. 자동 자막과 제작자 자막을 구분하며, 숫자나 고유명사의 오류는 음성 또는 화면과 대조한다. 자막의 마지막 시각과 영상 길이를 비교하고 중간 누락도 확인한다.
4. 필요한 장면을 추출하고 직접 열어 검토한다. 발언 시작 시각보다 완성된 도식이 뒤에 나타날 수 있다. 앞뒤 구간을 살펴 글자, 축, 단위, 출처가 읽히는 프레임을 선택한다. 임의의 장수 목표나 간격만으로 화면 확인을 끝내지 않는다. 시연과 동작은 정지 화면만으로 확정하지 않고 해당 구간을 재생해 확인한다.
5. 중요한 주장에 대해 원본 발언과 외부 검증을 구분한다. 주체, 범위, 기간, 단위와 전제를 보존하고 필요한 공식 자료를 대조한다. 현재 자료가 과거 영상의 수치를 대체하지 않도록 기준일을 따로 적는다. 계산을 추가하면 입력, 식, 단위, 가정과 결과를 저장한다. 모든 요약에 불필요한 외부 조사를 강제하지 않는다.
6. 원본의 핵심 내용과 결과물을 양방향으로 대조한다. 좁게 잡은 결론 때문에 중요한 사례나 절차를 누락하지 않는다. 제외한 내용은 중복, 요청 범위 밖, 정보 없음 등 이유를 기록한다. 접근하지 못한 핵심 구간은 미확인으로 보고한다.

## 분석 보조 모델

기존 Gemini 웹 계정이 사용 가능하면 구조 파악과 후보 시각 제안에 활용한다. 별도 유료 API로 자동 전환하지 않는다. 이미 충분한 원본 자료가 있거나 Gemini를 사용할 수 없으면 직접 분석한다. 기존 계정 설정과 개인 대화를 보존한다.

모델 응답이나 링크 카드, 모델의 재확인 발언은 독립적인 원본 증거가 아니다. 모델이 제안한 숫자와 시각은 후보로 취급한다. 직접 확보한 자막, 음성, 화면 또는 원기관 자료로 확인한다. 모델이 만든 표를 실제 영상 슬라이드로 소개하지 않는다.

## 남길 근거

작업별 비공개 폴더에 원본 식별 정보와 확보 경로, 자막, 내용 대조표, 장면 기록, 필요한 출처를 보관한다. 간단한 요청은 작은 파일 하나에 합쳐도 된다. 대조표에는 다음을 남긴다.

- 원본 구간과 핵심 내용, 결과물에서 설명한 위치
- 자막 확인, 음성 확인, 화면 확인의 각각의 범위
- 장면 파일과 원본 시각, 직접 검토 여부, 채택 또는 제외 이유
- 영상의 주장, 외부 확인 사실, 작성자의 해석과 계산의 구분
- 접근 실패와 남은 빈칸

`scripts/extract_frames.py`는 로컬 영상에서 프레임과 해시 기록을 만든다. 자동 생성한 `visual_review: pending`을 성공 상태로 간주하지 않는다. 직접 이미지를 연 다음 검토 내용과 채택 이유를 별도 대조표에 남긴다. 원본 영상 시각과 구간 파일의 로컬 시각을 혼동하지 않는다.

대용량 원본과 중간 산출물은 프로젝트의 저장 정책에 따라 NAS를 우선 사용한다. 실제 마운트, 권한과 여유 공간을 먼저 확인한다. 연결이 끊기면 해당 입출력을 중단하며 같은 이름의 로컬 디렉터리를 만들지 않는다. 작은 로컬 작업도 시작 전 용량 상한과 최소 여유 공간을 정한다.

## 전달과 완료

전체 자막 확인을 전체 영상 시청으로 표현하지 않는다. 장면 추출 성공, 시각 검토, 내용 분석 완료, 저장과 게시 성공은 각각 확인한다. 필요한 장면에는 원본 시간 링크와 짧은 설명을 붙인다. 썸네일이나 생성 이미지로 실제 장면을 대체하지 않는다.

글쓰기 요청에는 `readiz-writing`, Readiz 저장 요청에는 `readiz-blog`, 자료 위키 축적에는 `readiz-research-wiki`가 사용 가능할 때 해당 절차로 연결한다. 분석 스킬 자체는 저장과 게시 권한을 추가하지 않는다. 공개할 수 있는 근거와 비공개 초안 및 작업 기록을 구분한다. 작업용 탭과 이 작업이 만든 불필요한 임시 파일만 정리하고 검증본과 재개 기록은 보존한다.
