# 영상 확보와 프레임 추출

## 준비

`yt-dlp --version`, `ffmpeg -version`, `ffprobe -version`으로 도구를 확인한다. 없으면 기존 패키지 관리자 또는 격리된 Python 환경에 설치한다. 시스템 Python에 강제 설치하지 않는다. 재생목록 전체나 원본 최고 화질을 기본 다운로드하지 않는다.

오래된 Python에서는 최신 yt-dlp가 선택되지 않을 수 있으므로 설치된 버전도 확인한다. JavaScript 런타임 경고가 나오면 기존 Node 등 지원되는 런타임을 확인하고 `--js-runtimes node`처럼 명시한다. 누락된 포맷을 영상 자체의 해상도 제한으로 단정하지 않는다. 필요한 추가 구성은 [공식 EJS 안내](https://github.com/yt-dlp/yt-dlp/wiki/EJS)를 확인한다.

저장 위치와 여유 공간을 확인하고 이번 작업의 용량 상한을 정한다. 예를 들어 작은 로컬 시험은 총 512 MiB, 최소 여유 공간 2 GiB로 시작하고 원본이 크면 NAS를 사용한다. `--max-filesize`는 크기 정보가 없는 스트림과 ffmpeg 구간 다운로드에 대한 확실한 총량 제한이 아니므로 실제 파일 증가도 확인한다. NAS 정책은 작업 환경의 운영 지침을 따른다.

아래 `URL`과 `WORK`는 확인한 단일 영상 주소와 이미 준비한 작업 폴더다. 셸 변수는 항상 인용한다. 실행별 별도 폴더를 쓰고 기존 검증 파일을 덮어쓰지 않는다.

## 자막과 메타데이터 먼저

```sh
yt-dlp --ignore-config --no-playlist --skip-download --write-info-json \
  --write-subs --write-auto-subs --sub-langs 'ko.*,en.*' --sub-format vtt \
  --retries 1 --socket-timeout 20 -P "$WORK" -o '%(id)s.%(ext)s' "$URL"
```

필요한 언어만 선택한다. 성공 종료만으로 자막이 있다고 판단하지 말고 파일, 언어, 자동 생성 여부, 내용과 구간을 확인한다. `--list-subs`로 가능한 언어를 먼저 확인할 수도 있다. 메타데이터에는 임시 미디어 주소 등이 포함될 수 있으므로 그대로 공개하거나 Git에 넣지 않는다.

## 필요한 구간 확보

캡처용은 오디오 없이 읽을 수 있는 해상도의 영상만 받고, 발언 확인에는 음성도 확보한다. 화면 글자가 작으면 해상도를 높인다. 서로 먼 여러 구간이 필요하면 제한된 전체 다운로드가 반복 구간 요청보다 나은지 비교한다.

```sh
yt-dlp --ignore-config --no-playlist -f 'bv[height<=1080]/b[height<=1080]' \
  --download-sections '*80-95' --force-keyframes-at-cuts \
  --retries 1 --fragment-retries 1 --socket-timeout 20 \
  -P "$WORK" -o '%(id)s-80-95.%(ext)s' "$URL"
```

위 구간과 해상도는 예시다. 실제 후보에 맞춘다. `--force-keyframes-at-cuts`는 재인코딩 비용이 있으나 잘라낸 시작점의 정확도를 개선한다. 구간의 시작 시각을 작업 기록에 남기고 `ffprobe`로 길이와 스트림을 확인한다. 키프레임 절단, 타임스탬프 정규화나 다운로드 방식에 따라 오차가 생길 수 있으므로 원본 자막 또는 실제 플레이어와 장면을 대조하기 전에는 오프셋을 확정하지 않는다. 추출 도구의 요청 시각을 측정된 프레임 시각이라고 보고하지 않는다.

## 프레임 추출

```sh
python3 scripts/extract_frames.py --input "$WORK/video.mp4" \
  --output "$WORK/frames-run-1" --times 6 8 \
  --origin-offset 80 --source-url "$URL"
```

시간은 입력 파일 안의 초다. 위 예시는 원본 80초부터 받은 구간의 로컬 6초와 8초를 추출한다. 원본 86초와 88초에 해당한다는 값은 오프셋이 확인되기 전까지 잠정값이다. 전체 원본은 오프셋 0을 사용한다. 도구는 기존 출력 폴더를 거절한다. 실패 후에는 새 출력 폴더에서 재시도해 검증본을 보존한다.

직접 명령을 쓸 때도 표준 도구로 충분하다.

```sh
ffmpeg -nostdin -n -ss 86 -i "$WORK/full-video.mp4" \
  -map 0:v:0 -frames:v 1 "$WORK/frame-86.png"
```

각 이미지를 직접 열고 검은 화면, 전환, 불완전한 도식, 자막에 가려진 글자, 출처 잘림을 확인한다. 자막 오버레이는 프레임 파일에 별도로 합성하지 않아도 된다. 원본에 구워진 자막은 그대로 남는다. 내용 확인을 위해 필요한 원본 표기나 출처를 지우지 않는다.

## 실패와 브라우저 전환

오류 본문을 확인한다. 429는 요청을 멈추고 안내된 대기 조건을 따른다. 403, 인증 요구, 추출기 오류는 같은 요청을 반복하지 말고 버전과 원인을 확인한다. DRM 우회나 개인 쿠키 자동 추출, 계정 설정 변경을 대안으로 사용하지 않는다. 기존 로그인 브라우저에서 허용된 영상 재생과 자막 열람이 가능하면 그 경로로 전환한다. 추가 유료 API를 자동 사용하지 않는다.

브라우저에서는 원본 ID와 길이, 광고 여부, 실제 탐색 위치와 정지 상태를 캡처 전후 확인한다. 탐색 완료 응답만 믿지 말고 저장한 이미지를 연다. 자막만 확보했으면 자막 분석 범위를 밝히고, 핵심 화면에 접근하지 못했으면 미확인 구간을 남긴다.

공식 참고: [yt-dlp 옵션](https://github.com/yt-dlp/yt-dlp#usage-and-options), [FFmpeg 탐색과 프레임 출력](https://ffmpeg.org/ffmpeg.html). 도구 버전에 따른 차이는 설치된 도움말과 공식 문서로 확인한다.
