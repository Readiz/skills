# 디스크 정리

실제 여유 공간을 확보하면서 소스·개인 자료·운영 데이터와 작업 이력을 보존한다. 한국어로 대상, 확보 공간과 남은 제약을 알린다.

## 범위와 시작점

- 정리 요청은 확인된 재생성 가능 캐시·임시 파일과 검증 보관된 비활성 산출물의 정리를 포함한다. 같은 범위의 NAS 활용이나 항목마다 반복 승인을 요구하지 않는다. 검토만 요청했다면 삭제하지 않는다.
- 저장소의 `AGENTS.md`, 운영·저장·보존 문서와 설치된 정리 도구를 먼저 확인한다. 현재 checkout·운영 경로·실행 링크를 재확인하고 과거 기록의 경로·버전·보존 개수를 현재 규칙으로 단정하지 않는다.
- 최근 정리 영수증과 현재 잔여물을 먼저 대조한다. 같은 날 재요청돼도 새 실행 ID와 기준 가용 공간을 기록하고, 이전 회수량을 이번 결과에 합산하지 않는다. 기존 보관 도구의 미리보기에서 삭제 후보가 없으면 보존 개수를 줄여 대상을 만들지 않는다.
- `df -k`로 Mac의 가용 바이트를 기록한다. 필요한 범위에 한해 `du -x -k -d 1`로 큰 항목부터 좁힌다. 시스템 임시 경로 전체를 재귀 조사하지 않는다. 접근 거부와 읽지 못한 경로를 사용량 0으로 처리하지 않는다.
- 큰 다운로드·로컬 전체 복사를 시작하지 않는다. 로컬 임시 공간의 상한과 최소 여유를 작업 전에 정하고, 정리 기록은 작게 유지한다. 공간이 계속 감소하면 대형 작업을 시작하지 않고 완료분과 재개 지점을 남긴다.

## 대상 판단

| 대상 | 판단 기준 |
| --- | --- |
| 패키지 다운로드 캐시·컴파일 캐시 | 원본·lockfile·설치된 실행 환경과 구분하고 사용 중이지 않은 재생성 가능 항목부터 정리한다. |
| 작업트리의 의존성·빌드 캐시 | 비활성 작업인지, Git 추적 제외인지, 재설치·재빌드 방법과 필요한 원본이 있는지 확인한다. `node_modules`도 이름만으로 삭제하지 않는다. |
| 스크린샷·진단 출력·이전 배포본 | 검증 근거나 고유 산출물일 수 있다. 불필요한 중간물이라는 근거가 없으면 NAS 보관·재읽기 검증 후 로컬 정리를 검토한다. 현재본·문서의 복구본 보존 개수를 지킨다. |
| 소스·Git·작업트리·대화 기록·생성 이미지 | 캐시로 취급하지 않는다. 미커밋·미추적 자료와 앱 첨부를 포함해 보존한다. 작업트리 전체 정리는 앱의 보관 절차와 복구 가능성을 확인한다. |
| DB·세션·인증키·개인 문서·음원·금융 원장 | 기본 보존한다. 위치 이전이나 삭제가 요청 범위에 명시되지 않았다면 건드리지 않는다. |
| 휴지통·알 수 없는 대형 폴더·백업 | 이름·나이·크기만으로 삭제하지 않는다. 소유 목적·보존 정책이 불명확하면 해당 항목을 보존하고 필요한 선택만 묻는다. |

실행 중인 앱·빌드·서버의 열린 파일과 작업 디렉터리를 확인한다. 읽기 권한 문제로 확인할 수 없으면 해당 대상은 정리하지 않는다. 다른 작업을 강제 종료하거나 사용자 브라우저 세션을 닫아 공간을 만들지 않는다. 삭제 직전 경로·symlink·내용 변경·사용 여부를 재확인하고, 한정된 명시적 대상 목록만 처리한다. 저장소 전체 `git clean -fdx`나 홈·캐시 루트의 일괄 삭제를 피한다.

`cache` 경로에도 앱 실행 런타임·자동화 브라우저·빌드 도구가 설치될 수 있다. 폴더 이름만으로 다운로드 캐시와 동일시하지 않는다. 작업트리 의존성은 HEAD·작업 상태·manifest/lockfile 해시와 비활성 근거를 기록하고 삭제 후에도 대조한다. 최상위 디렉터리 mtime만으로 비활성을 판정하지 않는다. Git 인덱스 오류 등 검사 실패는 경로·오류와 함께 제외 기록에 남기며, 정리를 위해 인덱스를 재생성하거나 작업 상태를 초기화하지 않는다.

### Chrome 서명 임시 복제본

`code_sign_clone`의 APFS 공유 블록 때문에 `du` 합계가 SSD 전체보다 클 수 있다. 이를 회수 가능 공간으로 보고하지 않는다. 설치 버전뿐 아니라 실행 중인 Chrome의 실제 프레임워크 버전도 확인한다. 업데이트 뒤에도 이전 버전 프로세스가 실행될 수 있으므로 두 버전과 열린 clone을 보존한다. 한 clone 안에 여러 프레임워크 버전이 공존할 수 있으므로 앱의 `Info.plist` 버전만 보지 말고 해당 clone의 `Versions` 목록을 확인한다. 설치·실행 중인 버전이 하나라도 포함되면 그 clone 전체를 보존한다. 모두 이전 버전이며 사용하지 않음을 확인한 clone만 선별하고 프로필·쿠키·방문 기록은 대상에 넣지 않는다.

## NAS 보관이 필요한 경우

- 기존 프로젝트 NAS 구조와 보관 도구를 재사용한다. 연결 주소는 현행 운영 문서에서 확인하고 `mount`와 `df`로 원격 source·실제 SMB 마운트·읽기/쓰기·양쪽 여유 공간을 검증한다. 경로 존재만으로 NAS라고 판단하지 않는다.
- 마운트 루트를 새로 만들거나 끊긴 NAS 대신 같은 이름의 로컬 폴더에 쓰지 않는다. 연결·공간·권한 검증 실패 시 해당 입출력을 중단한다. NAS 관리 서비스나 공개 설정을 임의로 변경하지 않는다.
- 계산은 Mac에서 수행하고 큰 압축본·중간물은 NAS의 프로젝트·실행별 비공개 디렉터리로 스트리밍한다. 파일 목록·상대 경로·크기·SHA-256·symlink 정보를 남긴다. 복원에 필요한 권한·시각도 보존한다.
- NAS의 임시 이름에 쓴 후 NAS에서 다시 읽어 압축본과 파일별 내용·목록을 검증한다. 같은 파일시스템에서 최종 이름으로 바꾸고 영수증을 확정한다. 부분 완료와 완료를 구분하고 원본 변경·재마운트·검증 실패 시 로컬 원본을 유지한다.
- 로컬 삭제 직전에 원본 불변·NAS 검증본·실행 여부·보존 개수를 다시 확인한다. 필요한 배포 잠금을 사용한다. 보관 사본은 독립 백업이나 공개 허가를 뜻하지 않는다.

## 실행과 확인

- 작업별 비공개 기록에 기준 가용 바이트, 대상·판단 근거, 완료·건너뜀·오류, 보관 위치·검증 결과를 남긴다. 중단 후에는 기록과 실제 파일을 대조해 재개하고 완료 기록만 믿고 다시 삭제하지 않는다.
- 정리는 소규모 묶음으로 수행하고 실제 가용 공간과 남은 작업을 중간에 알린다. 실패한 항목을 전체 성공으로 표시하지 않는다. 다른 작업의 임시 파일이나 NAS 원본을 정리하지 않는다.
- `df` 전후 가용 바이트 차이와 삭제 파일의 할당량 합계는 별도로 보고한다. APFS 공유 블록·스냅샷·다른 프로세스 때문에 두 값은 다를 수 있다. 목표 용량을 맞추려고 보호 대상을 추가 삭제하지 않는다.
- 영향이 가능한 서비스는 작업 전후 같은 health·버전 경계로 확인한다. 인증 응답이나 health 성공을 실제 로그인·재생 성공으로 확대하지 않는다. 변경하지 않은 서비스 재시작·운영 배포를 정리의 기본 단계로 넣지 않는다.
- 완료 보고에는 실제 여유 공간 변화, 정리한 항목, 보관·복원 기록과 중요한 미완료만 짧게 적는다. 소스 변경이 있다면 해당 저장소에서 검사·커밋하고 전역 설치와 관리 원본이 같은 내용을 읽는지 확인한다.
