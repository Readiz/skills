# 작업트리 보관과 원본 이미지 공유

작업트리 전체를 비공개 NAS에 보관한 뒤 로컬에서 정리하거나, 여러 작업트리의 동일 원본 이미지에 APFS 저장 블록 공유를 적용할 때 읽는다. 일반 캐시 정리에는 이 절차를 추가하지 않는다. NAS 연결·용량·공개 범위와 실행 전후 측정은 상위 스킬의 공통 규칙을 따른다.

## 대상과 보호 근거

작업트리마다 실제 경로, Git 공통 저장소와 관리 디렉터리, 소유 채팅·첨부, 최근 작업 상태, HEAD·브랜치, Git 상태, 실행 중 사용 여부를 묶어 기록한다. 소유 채팅이 원본 checkout으로 돌아간 경우도 있으므로 현재 작업 경로뿐 아니라 정확한 작업트리 첨부 연결을 함께 확인하고, 삭제 직전에 두 관계를 다시 대조한다. 오래된 디렉터리나 큰 `du` 값만으로 미사용을 판정하지 않는다.

- 원본 checkout, 운영·배포 실행 경로, 실행 중이거나 열린 파일·작업 디렉터리가 확인되는 경로는 보존한다. 열린 파일 검사가 불완전하면 해당 경로를 미사용으로 간주하지 않는다.
- 최근 사용 여부는 채팅의 현재 상태와 마지막 작업 결과, 대기 메시지, 고정·활성 작업공간, 파일 사용 근거를 함께 본다. `idle`·`notLoaded`나 대화의 마지막 턴이 종료됐다는 사실만으로 작업 완료를 단정하지 않는다.
- 최근 사용 보호 기간은 이번 요청과 작업 특성에 맞게 정하고 실행 기록에 남긴다. 특정 실행의 일수를 모든 프로젝트의 상수로 만들지 않는다. 최근 작업이라도 완료·병합·보관 근거가 명확하면 별도 검토 대상으로 구분할 수 있으나, 현재 사용 여부와 변경사항 검사를 생략하지 않는다.
- 채팅·작업의 소유 관계가 불명확한 트리, 다른 저장소와 루트를 공유하는 트리, 앱 보관 작업이 대기·부분 완료된 트리는 보호한다. 조회 가능한 첨부가 없다는 사실은 미사용 근거가 아니다.
- Git 인덱스 오류, 진행 중 merge·rebase 등, 잠금 파일이나 Git 관리 상태의 이상은 제외 사유다. 정리를 위해 인덱스를 다시 만들거나 잠금을 지우거나 작업 상태를 초기화하지 않는다.
- 미커밋·미추적·무시된 파일은 기본 보존한다. 사용자가 변경 상태를 보존하는 비활성 작업트리의 보관·정리까지 요청했고 그 상태를 완전히 복원할 수 있을 때만 보관 대상으로 재검토한다. 원본 이미지 공유에서는 변경사항이 있는 작업트리를 제외한다.

이미 승인된 작업트리 정리 범위 안의 NAS 보관·검증은 대상마다 반복 승인을 요청하지 않는다. 복원 가능성을 입증하지 못한 경로는 남기고 이유를 기록한다. 안전한 대상이 없으면 그 결과를 그대로 보고한다.

완료 시각은 현재 사용 여부를 판단하는 보조 근거다. 마지막 실제 작업 결과와 이후 요청·대기 상태, 열린 파일, 소유 채팅·첨부, HEAD와 병합 근거를 함께 확인하고 대상별 판단을 기록한다. 오래된 답변에 남은 외부 환경 시험, 미구현 항목이나 인간의 선택을 작업트리 보관으로 완료·해결·승인 처리하지 않는다. 현재 작업 재개·대기가 없고 사용자가 요청한 보관 범위에 해당하면 파일 보관 여부를 별도로 검토할 수 있으나, 원채팅과 남은 항목의 상태·근거는 복원 안내에 유지한다.

실행 중 소유·활동 근거의 파일이 사라지거나 식별 정보가 바뀌면 해당 대상을 보호하고 원인을 구분해 기록한다. 근거 가용성의 변화만으로 새 작업이 시작됐다고 단정하지 않으며, 이미 완료된 보관·제거와 보호로 전환한 대상을 따로 확정한다.

## 보관 경로 선택

앱 관리 작업트리는 현재 앱이 제공하는 보관 도구와 첨부·소유 범위를 먼저 확인한다. 지원되는 경로라면 앱의 복구 가능한 보관 절차를 사용하고, 무시된 파일 등 그 절차에 포함되지 않는 자료는 별도로 보존한다. 도구가 로컬 작업트리를 즉시 제거한다면 사용자가 요구한 NAS 보관과 검증을 먼저 완료한다.

현재 채팅의 첨부가 아니거나 도구가 해당 작업트리를 처리하지 못하는 경우, 사용자가 요청한 범위 안에서 수동 Git·NAS 보관을 검토할 수 있다. 다음 조건을 모두 충족해야 한다.

- 앱 DB·내부 상태를 직접 수정하지 않고도 원본 파일, Git 상태와 이력을 독립적으로 복원할 수 있다.
- 앱의 진행 중 보관·복원 작업과 충돌하지 않는다. 임의로 작업을 취소하거나 다른 채팅의 소유권을 바꾸지 않는다.
- 수동 보관임을 기록하고, 원대화가 원래 작업 경로를 계속 참조할 수 있음을 알린다. 대화를 재개하기 전에 원경로를 복원하거나 앱의 지원 절차로 경로를 다시 연결하는 방법을 보관 기록에 포함한다.

수동 보관에 성공했다고 앱의 네이티브 보관까지 완료했다고 보고하지 않는다.

## 독립 복원에 필요한 자료

작업트리 파일 묶음과 Git 복구 묶음을 함께 만든다. 원본 저장소의 브랜치·HEAD·작업 인덱스를 바꾸거나 임의 커밋으로 정리하지 않는다.

| 자료 | 보존할 내용과 검증 경계 |
| --- | --- |
| 작업트리 전 파일 | 추적·미추적·무시된 파일, 경로와 파일 종류, 내용 해시, symlink 대상, 복원에 필요한 모드·소유권·수정시간·확장속성. 없는 파일과 삭제 상태도 구분한다. |
| 작업 상태 | HEAD의 detached·브랜치 상태, 원시 인덱스, staged·unstaged 변경과 파일 모드, `git status --porcelain=v1 -z --untracked-files=all`의 원시 바이트. |
| Git 관리 정보 | 원래 `.git` 연결 정보, 작업트리 관리 디렉터리, HEAD와 필요한 reflog·refs·설정. split index, sparse checkout, worktree별 설정 등 추가 의존성이 있으면 함께 보존하거나 지원하지 않는 대상으로 제외한다. |
| Git 객체와 이력 | HEAD·필요한 reflog 커밋·인덱스가 참조하는 객체를 포함하는 완전한 bundle 또는 동등한 독립 저장 형식. 원본 저장소의 object DB나 alternates에 의존하지 않아야 한다. |
| 복원 안내·도구 | 원래 경로와 Git 관리 경로의 대응, 보관 묶음의 해시와 목록, 요구 도구, 복원 순서, 검증 명령, 앱 연결 복구 범위. |

`git bundle --all`은 reflog에만 남은 커밋이나 인덱스에만 들어 있는 객체의 보존을 보장하지 않는다. 필요한 reflog 커밋과 원시 인덱스의 트리를 보관용 참조로 유지한 뒤 묶는다. 빈 저장소에 묶음을 가져온 다음 인덱스가 참조하는 각 객체도 존재하는지 확인한다. 인덱스 snapshot commit을 사용한다면 별도 인덱스 또는 원본을 바꾸지 않는 방식으로 만들고, 사용자 브랜치·HEAD·인덱스를 건드리지 않는다. 보관용 참조의 이름·목적·수명도 기록한다.

복원 시 원래 브랜치와 충돌을 피하려고 detached HEAD를 사용한다면 원래 브랜치 이름·참조를 보존하고 그 차이를 복원 안내에 명시한다.

Git diff 패치는 보조 자료다. 원시 인덱스나 전 파일 보관을 패치만으로 대체하지 않는다. staged와 unstaged 수정이 함께 있는 파일, binary 파일, 삭제·rename, ignored 자료를 각각 재현해야 한다.

하드링크·ACL·특수 파일·외부 symlink 의존성, 하위 저장소·submodule·LFS 등 일반 파일 묶음에 충분히 담기지 않는 구조가 발견되면 보관 도구의 지원과 독립 복원 가능성을 확인한다. 지원하지 못하는 대상을 누락하거나 평범한 파일로 변환해 성공 처리하지 않는다.

## NAS 보관·복원 검증·로컬 정리

파일 목록을 순회할 때 읽기 오류를 조용히 생략하지 않고 중단한다. symlink를 따라가지 않으며 다른 파일시스템·하위 마운트는 별도 대상으로 다룬다.

1. **입력 고정:** 대상 경로와 symlink, 실제 Git 저장소, HEAD·인덱스·파일 목록·해시를 기록한다. 활성 작업 여부를 재확인하고 해당 경로를 수정하는 다른 작업이 없을 때 진행한다. 보관 중에도 입력 변경을 감지할 수 있어야 한다.
2. **NAS 임시 보관:** 검증한 실제 원격 마운트의 프로젝트·실행별 비공개 영역에 스트리밍한다. 큰 로컬 사본을 먼저 만들지 않는다. 전 파일, Git 객체·관리 정보, manifest와 복원 도구를 같은 복구 단위로 묶는다.
3. **NAS 재읽기:** NAS에서 보관물을 다시 읽어 압축본의 무결성과 manifest의 경로·종류·크기·파일 해시를 대조한다. 압축 해제에 성공한 것만으로 검증 완료로 처리하지 않는다. 지원하는 메타데이터도 재확인한다. 심볼릭 링크는 대상 문자열과 링크 자체의 권한·속성을 보존하며 외부 대상을 따라가지 않는다. 복원 환경의 umask가 달라도 원본 링크 권한이 재현되는지 확인한다.
4. **각 작업트리의 실제 복원 시험:** 원본 Git object DB를 참조하지 않는 별도 저장소에서 복원한다. bundle의 선행 객체 의존성, 누락된 Git 관리 파일과 외부 경로 의존성을 확인한다. `.git` 연결 파일·`commondir` 등은 시험 저장소를 가리키도록 명시적으로 매핑하고, 원본 바이트와 시험용 치환 내용을 따로 보존한다. 원래 HEAD·인덱스·전 파일을 복원하고 Git 상태의 원시 바이트, 파일 해시·종류·지원 메타데이터를 대조한다. `git status`가 같아도 ignored 파일이나 이력이 누락될 수 있으므로 모든 검증을 함께 통과해야 한다. 시험 중 배포·신뢰 등록 등 외부 부작용이 있는 Git 훅은 일회성 옵션으로 격리하며 원본 설정을 변경하지 않는다.
5. **보관 확정:** 개별 압축본은 NAS 재읽기와 입력 불변 검증 뒤 같은 파일시스템에서 최종 이름으로 전환할 수 있다. 전체 복구 묶음의 완료 영수증과 삭제 허용은 독립 복원 시험까지 통과한 뒤 확정한다. 파일 검증 영수증을 전체 복구 완료로 해석하지 않는다. 시험용 파일만 정리한다.
6. **삭제 직전 재확인:** 채팅의 진행·대기 상태, 열린 파일·작업 디렉터리, Git 상태, HEAD·인덱스와 파일 manifest를 다시 대조한다. 실행 재개·새 파일·내용 변경·잠금·NAS 재연결이 발생했으면 해당 대상의 삭제를 멈추고 변경된 범위부터 검증한다.
7. **정확한 작업트리만 제거:** 복구 단위가 확정된 대상에 Git의 작업트리 제거 절차를 사용한다. 변경 상태 때문에 강제 제거가 필요하다면 보존·검증한 동일 경로와 동일 상태에만 한정한다. 루트 일괄 삭제, 다른 작업트리의 Git 관리 정보 정리, 저장소 전체 `git clean`을 사용하지 않는다.
8. **결과 확인:** 대상 경로의 제거, 나머지 작업트리·원본 저장소 상태의 보존, NAS 복원 자료의 존재와 실제 가용 공간을 확인한다. 작업트리별로 완료·제외·부분 완료를 기록한다.

복원 시험의 저장 공간과 파일시스템 기능을 먼저 확인한다. 한 번에 필요한 시험 공간을 제한하고, 공간 부족이나 권한·메타데이터 지원 문제로 충분한 시험을 못 하면 원본을 남긴다. 원본이 존재하거나 다른 작업이 같은 복원 경로를 사용 중이면 덮어쓰지 않는다. 원래 경로와 Git 관리 디렉터리 이름이 삭제 후 재사용되는 경우도 별도 시험한다. 스테이징 변경이 없어 인덱스 보관 커밋으로 HEAD를 재사용하는 경우도 검증한다.

### 대형 압축본의 검증 순회 합치기

대형 작업트리 압축본은 NAS 재읽기에서 압축 바이트 SHA-256과 tar member 검증을 같은 순차 읽기로 수행할 수 있다. 복원에서도 압축 SHA와 실제 파일 추출 또는 COW 바이트 대조를 한 번의 읽기에 결합한다. 이때도 삭제 직전 최종 압축 SHA 재확인은 유지한다. 이 구성의 대형 압축본 읽기는 보관 검증·복원·삭제 직전 확인의 세 번이며, 메타데이터·Git bundle 검증은 별도로 수행한다.

- 경로와 manifest 구조는 원본 접근이나 복원 경로 생성 전에 검증한다. 각 member를 쓰기 전에 경로·종류·크기·링크 대상도 확인한다. 복원 마지막에 압축 SHA를 확정하는 방식에서 오류가 나면 새 partial만 남기고 원본 제거로 넘어가지 않는다.
- tar 반복문의 자연 종료를 완전한 검증으로 보지 않는다. 마지막 예상 member를 처리한 즉시 tar 스트림 자체의 read-ahead 버퍼를 포함해 남은 padding과 EOF까지 읽는다. padding과 종료 영역은 모두 zero여야 하며 종료 영역은 최소 1024 bytes이자 512의 배수여야 한다. 뒤에 숨은 추가 member나 잘린 header도 거부한다.
- gzip CRC·ISIZE와 단일 gzip member, 압축 입력의 실제 EOF를 확인한다. 추가 gzip member, 압축 뒤의 raw bytes, 누락된 footer를 허용하지 않는다. 압축 파일의 처음 크기와 실제 읽은 바이트 수, seek 없음, fd와 경로의 전후 식별 정보, 최종 SHA를 검증 기록에 남긴다.
- 손상·잘림·trailing data 시험에는 공격 파일 자체의 올바른 SHA를 전달해도 구조 오류가 거부되는 경우를 포함한다. 단순히 압축 SHA가 다른 경우만 시험하지 않는다.

### 독립 Git 객체와 제한된 시험 공간

큰 Git 객체는 NAS의 이번 실행 전용 검증 저장소에 두고, Git 관리 디렉터리·refs·인덱스와 계산은 Mac에서 관리할 수 있다. 빈 저장소가 보관 bundle에서만 객체를 가져오도록 하고 원본 object DB, hardlink, `alternates`, 상속된 Git 환경변수에 의존하지 않게 한다. `objects/pack`을 NAS에 명시적으로 연결하는 경우 실제 마운트·정규 경로·실행 소유 표시·정확한 연결 대상을 시작과 실행 중에 확인한다. 다른 저장소의 pack 경로를 재사용하지 않는다.

bundle 가져오기와 `fsck`를 별도 저장소에서 통과시키고, 보존한 refs·HEAD·인덱스 트리·인덱스 전용 객체가 모두 존재하는지 대조한다. 로컬 loose object나 인덱스가 예상보다 커지지 않도록 관리 파일의 할당 상한을 별도로 둔다. NAS pack은 원본 object DB로 돌아가는 우회 경로가 아니어야 하며, 연결이나 소유 근거가 바뀌면 중단한다.

여유 공간이 충분하면 실제 대상의 파일을 NAS에서 모두 새로 쓰는 복원 시험을 우선한다. 부족한 경우에만 검증된 APFS COW 최적화를 선택할 수 있다. 선택은 새 복원 파일의 쓰기량·Git 인덱스·메타데이터·중단 여유를 포함해 실행 전에 고정하고, 실제 수행한 전략을 영수증에 기록한다.

NAS의 Git 임의 읽기가 실제로 느리고 Mac 여유 공간이 충분하면, 검증된 NAS bundle은 계속 보관하면서 이번 실행의 빈 독립 저장소에 bundle만 가져와 제한된 로컬 객체 캐시로 사용할 수 있다. 시작 전에 pack·전체 임시 공간의 상한과 최소 여유를 정하고, 원본 object DB·hardlink·alternates·상속 Git 환경변수를 참조하지 않는지 확인한다. 초기 가져오기와 전체 `fsck`, refs·인덱스 객체 대조를 통과한 이 캐시로 각 대상의 실제 복원 시험을 수행한다. 실행 중에도 공간과 캐시 경로·소유 표시를 감시하며, 소유 표시가 사라지면 검사를 건너뛰지 않고 중단한다. 모든 복원 시험과 시험 파일 정리가 끝나고 partial·등록된 시험 작업트리가 없으며 NAS 복구 자료가 유효한 경우에만 이번 실행의 캐시를 제거한다. NAS 단절이나 예산 초과 때 자동으로 로컬 방식을 선택하는 대체 경로로 사용하지 않는다.

공통 Git bundle 검증은 최초 NAS 전체 SHA-256과 참조, 독립 Git 저장소의 `fsck`와 필요한 인덱스 객체를 확인한 뒤 같은 batch 프로세스에서만 재사용한다. 열린 bundle과 부모 디렉터리, 경로와 마운트 식별 정보, 독립 객체와 참조 상태를 고정하고 각 복원 전후와 원본 삭제 직전에 다시 대조한다. 변경, 객체 추가, 재연결이나 프로세스 재시작이 있으면 재사용을 중단하고 새 batch는 최초 전체 검증부터 시작한다. 기본 사용자 복원의 전체 SHA-256과 개별 작업트리 보관본 검증은 유지한다. batch 종료와 검증용 캐시 삭제 직전에는 NAS bundle 전체 SHA-256을 각각 새로 계산하며, 성공하기 전에는 전체 완료 처리나 캐시 폐기를 하지 않는다. 실패하면 독립 캐시, 참조, 개별 완료 기록과 재개 지점을 보존한다.

원본을 제거하지 않은 실행의 종료는 복구 완료 처리와 구분한다. 실행 중단을 확정하고 원본 제거가 0건이며, 모든 원본과 필요한 Git 참조·객체가 남아 있고 검증 캐시에 유일한 자료가 없음을 확인한 경우에만 이번 실행의 재생성 가능한 캐시를 회수할 수 있다. 제거를 시작한 뒤 완료 여부가 불명확하거나 부분 제거 가능성이 있으면 이 종료 절차를 적용하지 않는다. 경로 존재와 제거 완료 0건만으로 원본 전체 보존을 인정하지 않는다. 정확한 소유 경로·표시·파일 목록과 식별 정보를 다시 대조하고, 부분 복원·시험 작업트리 등록·열린 파일·사용 프로세스가 없어야 한다. 원본·NAS 보관물·참조·실패 기록은 보존한다. 종료 근거와 회수 결과를 기록하고, 새 NAS 전체 해시를 수행하지 않았으면 이를 명시하며 보관·복원 완료로 보고하지 않는다. 원본이 하나라도 제거됐거나 유일 자료가 없음을 입증하지 못하면 기존 캐시 보존·복구 검증 절차를 유지한다.

### 선택적인 APFS COW 복원 시험

이 최적화는 새로 만드는 복원 시험 파일에 한정한다. 사용자의 원본을 교체하거나 수정하지 않는다. 원본 APFS 블록을 읽어 사용하는 시험이므로 실제 대상에 대해 원본 없이 전체 파일을 추출한 시험으로 보고하지 않는다. 원본이 없는 NAS 전용 복원 경로와 fixture를 계속 유지한다.

- 복제할 일반 파일을 미리 고정한다. 원본의 정규 경로, 같은 APFS 파일시스템, 단일 링크인 일반 파일, 전체 SHA·식별 정보·권한·확장속성·수정 시각을 확인한다. `.git` 연결 파일, 원시 인덱스, Git 관리 정보와 설정은 원본 재사용에서 제외하고 검증된 NAS 자료로 복원한다.
- 읽기 전용 `O_NOFOLLOW` fd로 원본 inode를 고정하고 `fclonefileat` 등 APFS clone 기능으로 존재하지 않는 새 파일만 만든다. 대상이 별도 inode·단일 링크인지 확인하고, 상속된 ACL이나 특수 플래그도 검사한다. 원본 변경이나 clone 실패를 일반 복사로 덮어 가리지 말고 중단한다.
- NAS 압축본을 끝까지 읽어 각 복제 파일의 모든 바이트와 직접 대조한다. 양쪽 EOF·크기·manifest SHA·압축 SHA를 함께 확인한다. 해시 확인만으로 바이트 대조를 생략하지 않는다. 최종 전 파일·메타데이터·HEAD·원시 인덱스·Git 상태 검증과 원본의 내용·식별 정보·ctime·mtime·속성 불변 검사도 유지한다.
- 별도 fixture에서 양쪽 쓰기와 메타데이터 변경의 독립성, 원본 제거 후 clone 유효성, 변경된 원본·다른 파일시스템·기존 대상·상속 ACL·NAS 바이트 불일치의 거부를 확인한다. clone 파일 수·논리 바이트·NAS에서 직접 대조한 바이트·실제 추출해 쓴 바이트를 구분해 기록한다.

### 예산 감시와 임시 복원본 정리

시험 중에도 실제 여유 공간과 임시 할당량을 감시하고 중단 여유를 둔다. 긴 Git 명령과 자식 프로세스는 이 실행만의 프로세스 그룹으로 관리하여 기준 위반 시 함께 중단한다. 공유 블록이 포함된 `st_blocks` 합계는 보수적인 작업 상한으로 사용할 수 있지만 추가 물리 사용량으로 단정하지 않는다.

복원 검증 결과를 임시 파일 삭제 전에 저장하고, `복원 검증 완료`와 `시험 파일 정리 완료`를 구분한다. 임시 경로를 실제로 삭제하는 동안 같은 경로를 재귀 순회하여 할당량을 측정하면 `ENOENT` 경합이 발생할 수 있다. 해당 실행의 marker·정규 경로·Git 작업트리 등록·시험 저장소 소유 관계로 정확한 삭제 대상을 확인한 뒤, 검증한 시험 저장소의 정확한 작업트리 제거 명령을 실행하는 동안만 삭제 중인 복원 경로와 Git 관리 파일의 재귀 할당량 순회를 생략한다. 다른 저장소나 다른 Git 명령에는 이 예외를 적용하지 않는다. 실제 free 기준, NAS 연결과 독립 pack 연결 검사는 계속 유지한다. 원본·NAS 보관물의 inventory 오류나 일반 Git 작업의 예산 검사를 함께 완화하지 않는다.

정리 중단 시 다음 후보로 넘어가지 않는다. 진행 marker, 저장된 검증 결과, 임시 Git 등록과 실제 남은 파일을 대조해 해당 실행의 잔여물만 복구·정리한다. 임시 삭제 실패를 원본 삭제 완료로 처리하지 않으며, 임시 정리가 끝나더라도 원본 제거 직전의 활동·상태·NAS 무결성 재확인은 다시 수행한다.

중단 후에는 영수증과 실제 NAS 파일, 원본 경로·Git 상태를 대조해 재개한다. `보관 작성`, `NAS 파일 검증`, `독립 복원 검증`, `로컬 제거`를 구분하고 뒤 단계가 미완료인데 전체 완료로 표시하지 않는다.

파일 식별 정보나 시각이 달라져 중단됐으면 내용이 같다는 이유로 검사를 완화하거나 실패 당시 기준·영수증·복원 시험 입력을 덮어쓰지 않는다. 정확한 변경 경로와 필드를 독립적으로 대조하고, 원인을 확인하지 못했으면 미확정으로 남긴다. 재개를 검토할 때는 변경분을 별도 개정본으로 보관·복원 검증하고, 과거 시험 증명을 활용하는 부분은 당시 실제 입력과 현재 파일·메타데이터·Git 객체·인덱스가 같다는 근거로 연결한다. 입증하지 못한 부분은 원본을 보존하고 다시 검증한다. 추가 변화가 감지되면 기준을 반복 갱신하지 않고 해당 실행의 보호 대상으로 전환한다. 이전 시험이 새 개정본까지 검증했다고 표시하지 않으며, 도구 작성·fixture 통과·실제 재개 성공을 구분한다. 삭제 직전의 현행 상태·활동·보관본 검사는 유지한다.

## 남길 작업트리의 APFS 이미지 공유

원본 파일의 내용과 경로를 유지하면서 동일한 Git 추적 이미지의 APFS copy-on-write 블록을 공유하는 절차다. 실행 중이거나 최근 사용한 작업트리, 변경사항·검사 오류가 있는 작업트리에는 적용하지 않는다. 보관할 작업트리는 먼저 보관 대상 여부를 결정하여 불필요한 공유 전환을 피한다.

- `du` 값과 이미지 내용 해시만으로 효과를 추정하지 않는다. 지원되는 APFS 메타데이터로 private bytes와 공유 상태를 확인하고, 이미 공유 중인 파일은 구분한다. private bytes는 공유 데이터·메타데이터 등을 제외한 값이므로 전체 물리 사용량이나 정확한 회수량으로 단정하지 않는다.
- 같은 APFS 파일시스템에서 작은 시험 파일로 `clonefile` 지원을 확인한다. 서로 다른 inode이며 한쪽을 수정해도 다른 쪽 내용이 바뀌지 않고, 필요한 권한과 확장속성이 보존되는지 검증한다. 하드링크나 일반 전체 복사를 공유 방식의 대안으로 사용하지 않는다.
- 원본·대상 모두 Git 추적 이미지이고 내용 해시, 모드, 소유자·그룹, 확장속성이 일치하는 파일만 선택한다. symlink·하드링크·ACL·특수 파일 플래그가 있거나 지원 범위를 벗어나는 파일은 제외한다. 최근 사용 보호와 Git clean 조건을 우회하려고 개별 파일만 골라 진행하지 않는다.
- 원본·대상의 식별 정보와 해시·속성을 기록한다. 대상 옆에 임시 clone을 만들고 대상의 수정시간을 보존한 뒤 내용·속성을 검증한다. 실제 교체 직전에 작업 활동과 양쪽 파일의 불변을 다시 확인한다.
- 같은 파일시스템의 원자 교체로 대상 하나만 전환한다. 원본 이미지를 수정하지 않는다. 교체 후 내용·권한·확장속성·수정시간과 HEAD·Git 상태가 유지되는지 확인하고 파일별 영수증을 남긴다. inode와 ctime은 바뀐다는 점을 기록한다.
- 작은 묶음의 결과와 `df` 가용 공간 변화를 확인한 뒤 범위를 넓힌다. 오류나 입력 변경이 생기면 해당 묶음을 멈추고 작업이 만든 임시 파일만 정리한다. 효과가 없다는 이유로 보호 대상까지 추가하지 않는다.

### 앱 갤러리와 프로젝트 원본의 공유

생성 이미지 중복 절감이 요청 범위에 포함되면 앱의 생성 이미지 갤러리와 프로젝트 원본 사이도 조사한다. 프로젝트 내부 중복만으로 전체 효과를 판단하지 않는다. 파일 크기·기존 해시로 후보를 좁힌 뒤 양쪽 전체 SHA와 APFS private bytes를 확인한다.

갤러리 대상은 현재 DB의 소유 채팅, 앱이 제공하는 현재 상태·마지막 턴, 최근 활동·고정·대기 작업과 열린 파일을 확인한다. 원시 rollout 경로가 없고 실제 `.jsonl.zst`가 존재하면 정규 경로·파일 식별 정보를 고정하고 압축 스트림의 `session_meta` ID를 소유 채팅과 대조한다. 이를 위해 전체 압축 해제 파일을 만들지 않는다. 실행 중 기존 근거가 사라지거나 바뀌면 중단한다.

비활성이 확인된 갤러리 파일만 같은 경로의 APFS clone으로 원자 교체할 수 있다. 활성 프로젝트 이미지는 읽기 전용 clone 원본으로만 사용하고, 작업트리 파일 교체의 보호 조건은 유지한다. 갤러리 이미지나 앱 기록을 삭제하지 않으며 하드링크를 만들지 않는다. 별도 inode와 쓰기 독립성을 확인하고, 대상의 내용·경로·소유자·권한·확장속성·생성시각·수정시각을 보존한다. 원본 불변과 양쪽 전체 SHA를 전후 대조하고 작은 묶음마다 영수증과 실제 여유 공간을 기록한다.

## 보고와 공유 범위

보관한 작업트리 수와 복원 위치·방법, 보호한 대상과 이유, 실제 `df` 전후 차이, APFS 공유 전환한 파일 수·논리 용량과 검증 범위를 나누어 보고한다. 다른 프로세스·스냅샷·공유 블록 때문에 실제 가용 공간 변화와 파일 할당량 합계가 다를 수 있다.

실행별 경로, 소유 채팅 식별자, 내부 주소, 원본 자료·비밀이 포함된 manifest는 비공개 운영 기록에 남긴다. 공개되는 스킬 본문이나 공개 파일 영역에 넣지 않는다.
