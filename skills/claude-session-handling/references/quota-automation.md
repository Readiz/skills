# 구독 Haiku 자동 호출

이 모드는 사용자가 예약 호출이나 기존 자동화를 요청했을 때만 적용한다. 세션 상태를 확인하려고 매번 모델을 호출하지 않는다. 기존 스케줄과 운영 원본, 중지 방법을 먼저 찾고 중복 예약을 만들지 않는다.

## 목적과 실행 주기

계정의 5시간 사용량 창을 시작하려는 짧은 요청은 한도를 늘리거나 사용량을 적립하지 않는다. 주간 한도와도 별개다. 해당 계정에서 실제 리셋 표시가 어떻게 바뀌는지 확인해야 하며, 단발 호출 성공만으로 새 창이 시작됐다고 보고하지 않는다.

다음은 실제 사용된 구성 예이며 모든 계정의 고정 규칙은 아니다.

- launchd가 60초마다 실행해 로컬 상태를 읽는다. 다음 예정 시각 전에는 서버를 조회하거나 모델을 부르지 않는다.
- 서버가 제공한 실제 리셋 시각에 30초의 여유를 둔 뒤 사용량을 다시 조회한다. 다른 세션이 이미 새 창을 시작했으면 추가 요청하지 않는다.
- 만료된 창에서만 구독으로 로그인한 Claude CLI의 Haiku에 짧은 응답 한 번을 요청한다. 창이 비활성인 응답과 조회 실패/누락을 구분한다. 확인 불가는 0으로 바꾸지 않는다.
- 조회 실패에는 제한된 backoff를 사용한다. 이 구성의 기본 예는 15분이다. 주간 한도 소진 때는 불필요한 모델 호출을 보류한다.

매분 로컬 확인, 서버 사용량 조회, Haiku 추론 요청의 세 주기를 따로 설명한다. 실제 실행 지연과 잠자기, 로그인 상태 때문에 지정 시각에 정확히 실행된다고 보장하지 않는다. 놓친 모든 회차를 몰아서 호출하지 않는다.

## 격리와 중복 방지

기존 작업 대화와 별도의 비대화형 호출을 사용한다. 도구/MCP/사용자 지침을 로딩하지 않는 최소 실행과 대화 저장 제외 옵션을 현재 버전에서 확인한다. `--bare`가 OAuth와 Keychain 인증을 건너뛰는 버전도 있으므로 구독 호출에 무작정 사용하지 않는다. API 키나 게이트웨이 환경변수를 상속해 별도 과금 요청으로 바뀌지 않도록 한다.

인증값은 기존 보안 저장소와 Claude 자체 인증 흐름을 사용하며 복사하거나 로그에 남기지 않는다. `auth status`의 갱신 동작도 버전에 따라 달라질 수 있다. 다른 버전의 관측만으로 만료 복구를 보장하지 않으며 refresh token을 직접 교환해 기존 다중 세션 인증을 망가뜨리지 않는다.

호출 전에 시도 기록을 원자적으로 확정하고 동시 실행 잠금을 사용한다. 서버가 계산한 리셋 타임스탬프의 소수점이 흔들릴 수 있으므로 원문 시간 문자열만으로 중복 키를 만들지 않는다. 비활성 응답에 고정 키 하나를 모든 기간에 재사용하지 않는다. 직전 관측 활성 창의 종료 등 확인된 전이 근거로 비활성 기간을 구분하고, 새 응답으로 관측값을 덮기 전에 그 근거를 보존한다. 활성 관측 없이 시작한 비활성 상태는 다음 기간을 추측하지 않는다.

기존 상태에 과거 비활성 시도 표식과 현재 활성 창 관측이 함께 남아 있으면 상태 파일을 지워 복구하지 않는다. 관측된 활성 창 종료 뒤 비활성 응답은 구별되는 새 기간으로 처리할 수 있어야 한다. 같은 비활성 기간의 재확인, timeout/crash, 호출 뒤 사용량 조회 실패는 불확실한 요청의 재전송을 막아야 한다. 회귀 검증은 실제 상태 전이와 호출 횟수를 확인한다. 여러 기간이 연속으로 진행되는 경우와 사람이 중간에 새 활성 창을 연 경우를 포함한다.

예약 실행의 exit 0이나 매분 실행 기록만으로 Haiku 호출 성공을 판정하지 않는다. `last_ping_at`과 해당 호출 시각의 이벤트를 대조해 실제 호출, 미호출, 결과 불명을 구분한다. 상태에 복사되어 남은 과거 `last_ping` 값은 새 호출 증거가 아니다. 매분 로컬 확인 시각, 최근 서버 사용량 조회 시각, 실제 모델 호출 시각도 서로 구분해 보고한다.

기존 자동화의 승인된 범위 안에서 확인된 누락을 보완할 때 같은 승인을 반복해서 요구하지 않는다. 다만 별도로 승인되지 않은 Claude bridge-pointer나 다른 설정 변경으로 범위를 넓히지 않는다. 코드만 변경할 때는 해당 코드 파일을 백업하고 잠금 및 원자적 교체를 사용한다. 전체 installer는 전역 모델, 알림 또는 세션 설정을 다시 덮을 수 있으므로 코드 배포 경로로 사용하지 않는다. 다음 실제 창 경계에서 호출과 관측을 확인하기 전에는 자동화가 완전히 정상이라고 보고하지 않는다.

로그는 시각, 상태, 다음 확인 시각과 모델 증거만 제한된 크기로 저장한다. 원문 응답, 인증값과 불필요한 세션 ID는 남기지 않는다. 활성화와 중지/삭제 방법을 함께 남기고 다른 Remote Control 서비스와 분리한다.
