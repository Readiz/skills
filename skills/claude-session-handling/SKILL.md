# Claude 세션 관리

서버 재시작, 기존 대화 재개, 모델 변경, 서브에이전트 반영과 예약 호출은 서로 다른 작업이다. 요청받은 범위를 수행하고 각 결과를 따로 확인한다. 이 스킬을 읽었다는 사실만으로 기존 세션 종료, 모델 호출이나 예약 등록을 시작하지 않는다.

## 먼저 상태를 확인한다

운영 상태의 판단이 필요할 때 다음 읽기 전용 도구로 등록된 세션을 확인한다. 이미 제공된 설정의 의미나 주기 설명만 요청했다면 관련 없는 세션/인증 조회를 늘리지 않는다. 경로는 이 스킬 폴더 기준이다.

```sh
python3 -B scripts/inspect_sessions.py --project /path/to/workspace
```

- 로컬 대화 ID, 원격 대화 ID, PID, 작업 경로와 `idle`/`busy`를 구분한다. `claude agents --json`이 비어도 Remote Control의 SDK 자식 세션이나 권한 제한 때문일 수 있다. 목록 하나만 보고 세션이 없다고 판단하지 않는다.
- 실행 중인 바이너리와 설치 링크의 실제 대상을 대조한다. 자동 업데이트로 버전이 달라질 수 있다. `CLAUDE_CONFIG_DIR`, 사용자 설정, 프로젝트 설정과 실제 LaunchAgent 실행 폴더도 확인한다.
- 샌드박스에서 `ps`나 Keychain 조회가 막히면 확인 불가로 기록한다. 그 결과만으로 프로세스가 없거나 구독 로그인이 풀렸다고 단정하지 않는다. 필요한 권한으로 해당 조회만 재시도한다.
- 전체 프로세스 인수, Keychain 원문, 세션의 `.key` 파일, 인증 헤더나 임시 SDK URL은 출력하지 않는다. 진단 결과도 비공개 자료로 취급한다.

## 요청에 맞는 절차를 따른다

- **재시작과 복원:** [세션 복구 절차](references/session-recovery.md)를 읽는다. 기존 ID와 대화 기록을 먼저 확보하고 실행 중인 장시간 작업을 보호한다.
- **공통 모델과 서브에이전트:** 아래 반영 기준을 적용한다. 기존 파일은 백업 후 병합하고 프로젝트별 규칙과 명시적인 모델 선택을 보존한다.
- **Haiku 핑과 5시간 창:** [구독 자동 호출](references/quota-automation.md)을 읽는다. 로컬 실행, 서버 조회, 실제 모델 호출 시각을 구분하고 실제 호출 전에는 창 전이가 검증됐다고 단정하지 않는다.

## 모델과 서브에이전트 반영

- 사용자 기본 모델과 현재 세션의 모델은 별개다. 기본값을 Opus로 설정해도 사용자가 고른 Fable 등을 일괄 변경하지 않는다. 원하는 모델 변경이 이미 승인됐다면 그 범위에서 적용한다.
- `~/.claude/agents/<name>.md`의 `model: sonnet`처럼 하위 모델을 명시할 수 있다. 메인이 Fable이면 Fable이 설계와 검토를 맡고 Sonnet이 구현하는 구성도 가능하다. 지침이나 description을 특정 메인 모델에만 맞춰 다른 명시적 선택을 무효화하지 않는다.
- YAML, 지원 필드와 로딩 여부를 확인한다. 에이전트 파일 설치는 실제 위임 성공의 증거가 아니다. 실행 검증이 필요하고 승인 범위에 들면 별도 대화에서 작게 확인하며 기존 작업 대화에 시험 메시지를 넣지 않는다.
- 기존 에이전트 폴더의 파일 변경 감지와 새 폴더의 최초 생성은 다를 수 있다. 현재 버전의 로딩 동작을 확인하고 필요한 세션만 재개한다. 설정 파일의 `model` 변경이 실행 중인 모델까지 바꿨다고 보고하지 않는다.
- 프로세스의 `--model`은 시작 인수다. 사용자가 실행 중 모델을 바꿨을 수 있으므로 현재 선택과 최신 실제 응답의 모델 증거를 구분한다.

## 승인과 결과 보고

기존 사용자 승인과 제한을 유지한다. 같은 승인에 특별한 문구를 요구하며 반복 확인하지 않는다. 다만 진행 중인 렌더링 중단처럼 새로 드러난 영향이 승인 범위를 벗어나면 그 구체적인 결정을 확인한다.

자동 승인 검토가 거절하면 대상 동작과 이유를 알린다. 허용되는 안전한 대안을 검토하되 거절된 내부 파일 수정을 직접 API, 다른 도구나 지연 실행으로 우회하지 않는다. 이후 사용자가 구체적인 동작을 승인했다면 그 새 근거로 정상적인 검토 절차를 거친다. 여전히 거절되면 해당 동작을 실행하지 않고 미완료 범위를 명확히 남긴다. 스킬 자체가 추가 승인 절차를 만들거나 도구의 거절을 해제하지는 않는다.

결과에는 다음 중 실제 확인한 것만 적는다: 서버 재연결, 원래 대화 ID 유지, 각 대화의 실행 재개, 현재 모델, 서브에이전트 로딩/실행, 예약 등록/실제 호출. HTTP 200, `Connected`나 capacity만으로 전체 복원이 끝났다고 하지 않는다. 남은 대화 수와 작업 중인 세션, 차단된 동작을 숨기지 않는다.

공식 기준은 [Remote Control](https://code.claude.com/docs/en/remote-control), [서브에이전트](https://code.claude.com/docs/en/sub-agents), [설정 우선순위와 반영](https://code.claude.com/docs/en/settings)이다. 설치 버전과 실제 동작이 다르면 그 차이를 기록하고 현재 환경의 증거를 우선한다.
