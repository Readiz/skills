# Claude Code 공통 작업 지침

메인 Opus가 요구사항과 설계, 작업 분해와 최종 검토를 맡고, Sonnet 에이전트가 범위가 명확한 구현과 테스트를 맡는 구성입니다. 여러 프로젝트에서 같은 에이전트 정의를 공유하면서 각 세션의 대화와 진행 중인 작업을 보존합니다.

정리 기준: 2026-10-27. 아래는 사용자 공통 설정과 적용 절차의 예시입니다. 실제 적용 시 설치된 Claude Code 버전과 계정, 프로젝트 설정을 확인합니다.

## 역할과 공유 범위

| 역할 | 모델 | 맡길 일 |
| --- | --- | --- |
| 메인 | `opus` | 요구사항, 설계, 중요한 판단, 작업 조정과 최종 검토 |
| `sonnet-implementer` | `sonnet` | 일반 기능 구현, 버그 수정, 리팩터링과 테스트 |

같은 OS 사용자와 Claude Code 설정 디렉터리를 사용하는 프로젝트에서는 사용자 범위 에이전트 정의를 공유할 수 있습니다. 실제 에이전트 실행과 컨텍스트는 각 세션에 속합니다. 모바일 화면에서 여러 세션이 보이더라도 실행 계정과 설정 위치는 각각 확인합니다.

Claude Code는 사용자 범위 `~/.claude/agents/`와 프로젝트 범위 `.claude/agents/`의 정의를 지원합니다. 적용 범위와 같은 이름의 정의가 겹칠 때의 처리는 [공식 Subagents 문서](https://code.claude.com/docs/en/sub-agents)를 참고합니다.

## 사용자 공통 파일 예시

```text
~/.claude/
├── settings.json
├── CLAUDE.md
└── agents/
    └── sonnet-implementer.md
```

기존 권한과 Hook, 플러그인 및 프로젝트 설정을 보존하면서 필요한 부분만 병합합니다. Codex의 `~/.codex/` 설정은 별도로 관리합니다.

### sonnet-implementer.md

다음 내용을 `~/.claude/agents/sonnet-implementer.md`에 둘 수 있습니다. YAML frontmatter의 설명은 위임할 상황을, 본문은 구현 시 지킬 범위를 정합니다. [공식 파일 형식](https://code.claude.com/docs/en/sub-agents#write-subagent-files)

```markdown
---
name: sonnet-implementer
description: 일반 기능 구현, 버그 수정, 리팩터링과 테스트에 사용합니다. 메인이 요구사항과 범위를 정한 뒤 구현을 우선 위임할 수 있습니다.
model: sonnet
tools: Read, Glob, Grep, Edit, Write, Bash
---

부모가 전달한 요구사항과 수용 조건에 맞춰 구현한다.
기존 프로젝트 규칙과 사용자의 변경을 보존하고 무관한 리팩터링을 피한다.
다른 에이전트와 같은 파일을 동시에 바꾸지 않도록 부모와 조정한다.
변경에 맞는 테스트를 수행한다.
모호한 설계나 반복 실패는 근거와 함께 부모에게 돌려보낸다.
작업 후 수정 파일, 수행한 검사, 결과와 남은 문제를 보고한다.
```

### CLAUDE.md 공통 문안

기존 `~/.claude/CLAUDE.md`에 다음 취지의 지침을 추가합니다.

```markdown
## 구현 에이전트 활용

- 메인 Opus가 요구사항과 설계, 작업 분해와 최종 검토를 맡는다.
- 일반 구현, 버그 수정과 테스트는 sonnet-implementer에 우선 위임한다.
- 아주 작은 수정이나 위임 비용이 더 큰 작업은 메인이 직접 처리한다.
- 위임할 때 범위, 수용 조건, 대상 파일과 필요한 검사를 함께 전달한다.
- 독립된 작업만 병렬화하고 같은 파일의 동시 변경을 조정한다.
- 메인이 구현 결과와 검사 근거를 검토한 뒤 사용자에게 보고한다.
- 위임할 수 없으면 이유와 실제 수행 방식을 알린다.
```

### settings.json 병합 예시

```json
{
  "model": "opus"
}
```

위 조각은 메인 모델의 기본값입니다. 기존 파일의 다른 키는 유지합니다. 실제 세션에서 선택한 모델과 프로젝트 설정도 확인합니다.

## 기존 세션을 보존하며 적용하기

1. `claude --version`과 실제 실행 계정, 설정 위치를 확인합니다. 기존 파일을 비공개로 백업하고 프로젝트별 설정과 충돌을 살펴봅니다.
2. 역할 파일, 공통 지침과 모델 설정을 병합하고 JSON 및 YAML 문법을 검사합니다.
3. 시험 세션에서 에이전트가 인식되는지 확인하고 작은 구현 작업을 명시적으로 위임합니다. 실제 Sonnet 실행과 수정 결과, 검사 근거를 확인합니다.
4. 기존 작업 세션은 대화와 실행 상태를 유지한 채 반영 여부를 확인합니다. 정의가 보이지 않으면 작업을 보존하고 안전한 재개 시점에 적용합니다.
5. 설정 저장, 에이전트 인식, 실제 위임과 기존 작업 보존을 각각 보고합니다.

기존 세션에 다음처럼 요청할 수 있습니다.

```text
현재 작업 내용과 대화를 유지해.
공통 설정과 sonnet-implementer가 인식되는지 확인해줘.
메인 Opus가 설계와 검토를 맡고, 일반 구현과 테스트는
sonnet-implementer에 우선 위임해줘.
```

현재 공식 문서는 에이전트 디렉터리의 변경 감지를 지원한다고 설명하며, 디렉터리를 처음 만든 경우 등 다시 시작해야 하는 조건도 안내합니다. 설치 버전과 세션 시작 조건을 확인해 반영 방법을 정합니다. [공식 정의 갱신 안내](https://code.claude.com/docs/en/sub-agents#write-subagent-files)

기존 세션에서 별도 모델을 선택했다면 그 선택도 함께 확인합니다. 세션 복원과 Remote Control 진단이 필요하면 저장소의 [claude-session-handling](../skills/claude-session-handling/SKILL.md)을 참고합니다.

## Haiku 주기 호출 설계

작업을 시작하기 전에 짧은 Haiku 요청을 보내 5시간 사용량 창의 시작을 유도하려는 운영안입니다. 약 5시간마다 요청하는 방식을 기본으로 하며, 경계 직전 호출을 피하기 위한 초기 후보 간격은 5시간 5분, 즉 18,300초입니다. 새 창의 실제 시작 여부는 해당 계정의 Usage 표시로 확인합니다.

Claude의 유료 플랜에는 5시간마다 초기화되는 세션 한도와 주간 한도가 있으며, Claude Code를 포함한 여러 Claude 제품의 사용량이 함께 계산됩니다. [공식 사용량 안내](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)

짧은 호출도 사용량을 소비합니다. 이 설계는 시작 시점을 맞추려는 것이며 한도를 적립하거나 주간 한도를 늘리는 기능은 제공하지 않습니다. 공식 사용량 안내만으로 모든 계정에서 단발 호출이 새 창을 시작하는 세부 동작까지 확정할 수는 없습니다.

구현을 별도로 요청할 때 다음 조건을 함께 전달합니다.

- 구독으로 로그인된 Claude Code CLI를 사용하고 API 키나 게이트웨이 환경변수가 다른 과금 경로로 바꾸는지 확인합니다.
- 기존 작업 세션과 분리된 비대화형 요청으로 짧은 응답 한 번만 받습니다. CLI 예시 `claude -p --model haiku "ping"`은 설치 버전의 도움말과 대조합니다.
- macOS에서는 LaunchAgent 같은 실행기를 사용할 수 있습니다. 동시 실행 잠금, 중복 방지, 제한된 실패 재시도와 작은 로그를 둡니다.
- 로그에는 요청 시각, 성공 여부와 확인한 리셋 시각을 남기고 인증값과 대화 원문은 남기지 않습니다.
- 잠자기와 재부팅, 로그인, 네트워크 실패로 실행이 늦어질 때의 재개 및 중단 방법을 정합니다. 놓친 요청을 한꺼번에 보내지 않습니다.
- 호출 전후 Usage를 비교하고 실제 만료 경계 뒤의 새 창 생성까지 확인합니다. 단발 응답 성공과 예약 프로세스 실행, 새 사용량 창 생성을 구분합니다.

서버의 실제 리셋 시각을 기준으로 이미 시작된 창의 중복 호출을 피하는 운영 방식도 있습니다. 저장소의 [구독 Haiku 자동 호출 참고](../skills/claude-session-handling/references/quota-automation.md)는 그 구성과 진단 방법을 다룹니다. 고정 간격 호출안과 서버 시각 기반 구현은 구분해 적용하고, 기존 자동화가 있으면 그 주기와 상태부터 확인합니다.
